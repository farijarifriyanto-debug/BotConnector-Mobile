# Design: BotConnector iOS/iPadOS 2.1.0 — BYOK Standalone Client

Date: 2026-11-05
Status: APPROVED (owner, 2026-11-05) — amendments incorporated: PalsHub marketplace only removed (local pals kept); Anthropic transport full-featured
Refs: App Review rejection Guideline 3.1.1 (build 2.0.0 (115)); Kelivo (https://github.com/Chevey339/kelivo) as UX reference; local fork at `C:\Users\farij\Projects\botconnector-chat-flutter`.

## Intent & Why

App Store Review rejected build 2.0.0 (115) under Guideline 3.1.1 because the app gates paid AI services behind a BotConnector account login. The fix is to make the iOS/iPadOS app a **standalone BYOK (bring-your-own-key) AI chat client**: the user configures any compatible provider with their own API key and the app talks **directly** to that provider's endpoint. No BotConnector account, no balance, no credits, no subscription, no checkout.

China mainland has already been removed from distribution in App Store Connect (owner action, done).

## Goals

1. Remove every iOS/iPadOS dependency on BotConnector account, balance, credits, subscription, and checkout.
2. Core flow (mirroring Kelivo Settings → Providers): pick a provider preset or enter a custom OpenAI-compatible endpoint → enter API key → load model list → pick model → chat. No wizard, no BotConnector login.
3. API keys stored **only** in iOS Keychain; never written to logs or analytics.
4. Helpful, actionable error messages for: invalid key, network failure, empty model list.
5. Preserve existing local chat history (WatermelonDB) across the app update.
6. Version 2.1.0, build 124.
7. Draft App Store Review Notes (English) explaining the region change, BYOK mechanics, and reviewer test steps with a placeholder limited test key.
8. Verification via GitHub Actions (macos-26): typecheck, lint, jest, iOS simulator build. Physical-device testing happens after a TestFlight build; until then marked **BELUM TERVERIFIKASI**.

## Non-goals / Anti-goals

- No new wizard or onboarding gate (Kelivo has none; a snackbar/prompt on send-without-model is the pattern).
- No redesign of the chat UI (pertahankan UI chat BotConnector).
- No server-side changes; no Android release work (shared RN code changes will technically affect Android source, but no Android build is shipped from this work).
- No in-app purchase, no BotConnector key as a login substitute to unlock the same paid service (BotConnector appears only as a BYOK preset where the user supplies their own API key, like any other provider).
- Anthropic native streaming transport is included (Claude is a "common provider" per owner), but no other new transports.

## Constraints

- RN code is shared iOS/Android; removals are done in shared UI/navigation but scoped to shipping only an iOS build.
- iOS marketing version is pinned in `ios/PocketPal.xcodeproj/project.pbxproj` and guarded by `scripts/release-preflight.sh` — both must be updated together to 2.1.0.
- Build number: set to 124 in the release pipeline (Codemagic `BUILD_NUMBER` / pbxproj `CURRENT_PROJECT_VERSION`).
- `react-native-keychain` is already the established secret store (4 existing features use it).
- Existing `ByokProviderStore` + `AddProviderSheet` are 80% done but never wired into chat; the working chat path is `ServerStore` (OpenAI-compatible servers) → `ModelStore.setRemoteModel` → `OpenAICompletionEngine` → `streamChatCompletion` (SSE over XHR).

## Approaches considered

| Approach | Trade-offs | Decision |
|---|---|---|
| **A. Bridge BYOK into ServerStore** — saving a provider in `ByokProviderStore` upserts a `ServerStore` server + selected models, reusing the tested chat path. Remove Cloud UI. | Minimal new code; reuses tested streaming/model-picker paths; small diff | **Chosen** |
| B. New Kelivo-style provider engine (ProviderConfig + per-kind transports) replacing ServerStore | Cleaner long-term, but rewrites the tested chat path; high risk close to resubmission | Rejected |
| C. No presets — manual server entry only | Smallest diff, but fails the Kelivo-flow requirement and gives reviewers a worse first run | Rejected |

## Design

### 1. Provider presets (BYOK)

Preset registry (all OpenAI-compatible transport unless noted), extending the existing `src/api/byokProviders.ts`:

- OpenAI — `https://api.openai.com/v1`
- Anthropic (Claude) — `https://api.anthropic.com/v1` — **native `/messages` transport** (new, see §4)
- Google Gemini — `https://generativelanguage.googleapis.com/v1beta/openai`
- DeepSeek — `https://api.deepseek.com/v1`
- OpenRouter — `https://openrouter.ai/api/v1`
- xAI (Grok) — `https://api.x.ai/v1`
- Mistral — `https://api.mistral.ai/v1`
- BotConnector — `https://api.botconnector.id` (BYOK preset; user pastes their own `bc_…` API key — no login, no account UI)
- Custom — user-supplied base URL (OpenAI-compatible)

### 2. BYOK → chat bridge (the missing 20%)

- On **save** in `AddProviderSheet`: upsert a `ServerStore` server (`serverType: 'OpenAI'`, or Anthropic profile) named after the provider, write the key via `serverStore.setApiKey` (Keychain `pocketpal-server-<id>`), and set the checked models into `serverStore.userSelectedModels`.
- On **remove**: delete the server + its Keychain key + deselect its models.
- Keep `ByokProviderStore` as the preset/config metadata store; ServerStore remains the single source for chat routing. No changes to `ChatView`, `ChatInput`, or the model picker beyond removing Cloud entries and making "Add provider" a first-class entry in the picker.

### 3. Remove Cloud account surface (iOS UI)

- Delete `BotConnectorAuthStore` usage: `useDeepLinking` restore/revalidate, auth callback (`botconnector://auth/callback`) handling, `BotConnectorAccountCard` (Settings "Account" section), Cloud preset in `RemoteModelSheet`, "Connect account" buttons (`ChatView`, `ChatPalModelPickerSheet`), capability gating tied to Cloud login (`mobileFeatureAccess`, `capabilityDenial` Cloud branches), PAYG/balance display (`paygStatus` surfaces).
- Delete Cloud-only API modules from the app surface: `botconnectorAccess`, `botconnectorCatalog`, `botconnectorFiles`, `botconnectorMedia`, `clientDevices`, `config/botconnectorLocal`.
- Remove screens/features that depend on Cloud: **AI Images** (Cloud media), **PalsHub marketplace** (Supabase/Google Sign-In/Stripe checkout — already flag-disabled), **BotConnector Local** device pairing. Unregister from drawer/navigation; remove dead dependencies where cleanly separable. **Local pals (user-created personas, pal-switching in chat, `chat://` deep links) are KEPT** — owner decision 2026-11-05; they are local-only, account-free, and match Kelivo's assistants.
- Keep: local GGUF models (HuggingFace), web-search BYOK (`SearchProviderStore`), chat history, settings.

### 4. Anthropic native transport (full-featured — owner decision)

- New `streamAnthropicCompletion` (POST `{base}/messages`, headers `x-api-key` + `anthropic-version`, SSE), dispatch by server type in `completionEngines`, same error mapping (401/429/network) as the OpenAI path. **Complete, not minimal**: system-prompt extraction, `max_tokens` (required by the API — sensible default), temperature/top_p, stop sequences, streaming text deltas, **tools** (`tools`/`tool_use`/`tool_result` blocks), **vision** (base64 image blocks from local images, mirroring the OpenAI path's image inlining), and **extended thinking** (thinking blocks surfaced as reasoning, parity with the OpenAI reasoning passthrough). Jest-covered with mocked XHR like `openai.test.ts`.

### 5. Error handling (user-fixable messages)

- Invalid key (401/403): "API key ditolak — periksa kembali key di Settings" (+ en).
- Network failure: "Tidak bisa terhubung ke endpoint — periksa URL dan koneksi."
- Empty model list (200 with `data: []`): "Provider merespons tapi tidak ada model — periksa akses akun provider Anda." (Fixes the class of bug where empty list is shown as a generic failure.)
- No key material in any log line; audit `console.*` in touched files.

### 6. Upgrade migration (history preservation)

- No WatermelonDB schema change — chat history untouched.
- On first run of 2.1.0: remove the auto-created "BotConnector" Cloud server entry **only when both** its URL matches `api.botconnector.id` **and** the OAuth session Keychain entry (`botconnector-native-auth-v1`) exists — a manually-added server at the same URL with the user's own key is preserved. Then delete the OAuth Keychain entries (`botconnector-native-auth-v1`, `botconnector-native-login-pending-v1`). Leave all user-added servers, BYOK keys, and chat sessions intact. One silent migration flag in `UIStore` (persisted).

### 6b. Builder-check decisions (settled 2026-11-05)

1. **BotConnector BYOK = a plain server**: all Cloud special-casing is removed from `ServerStore` (`isBotConnectorApiUrl` capabilities/catalog enrichment, `refreshBotConnectorAccess`, `botConnectorPayg`, `listCaps`/display-name/vision/web-search badge enrichment sourced from the Cloud catalog). A BYOK BotConnector server behaves exactly like any OpenAI-compatible server — raw model IDs, no account calls. The `botconnectorAccess`/`botconnectorCatalog` modules are deleted, not merely hidden.
2. **Pals**: marketplace removed, local pals kept (see §3).
3. **Build number 124**: floored in `codemagic.yaml` (`agvtool new-version -all` with `max($BUILD_NUMBER, 124)` semantics) and `CURRENT_PROJECT_VERSION = 124` in pbxproj as fallback. The 2.1.0 version string in App Store Connect is an owner action at submission.
4. **Anthropic transport**: full-featured (owner decision) — see §4.
5. **Settings → Providers surface**: a "Providers" section is added to `SettingsScreen` listing configured BYOK providers (tap → re-open `AddProviderSheet` to edit key/models/remove), for Kelivo parity; the existing model-picker entry stays.

### 7. Versioning & CI

- `project.pbxproj`: `MARKETING_VERSION = 2.1.0`, `CURRENT_PROJECT_VERSION = 124` (all 6 config spots); `scripts/release-preflight.sh` guard updated 1.0 → 2.1.0; ensure the release pipeline emits build 124.
- GitHub Actions (existing `ci.yml`, runner `macos-26`): typecheck, lint, jest, `release-preflight.sh`, iOS simulator build (`yarn ios:build`). Add/adjust jobs only as needed — no Codemagic changes in this design beyond build-number sourcing.
- Docs: `docs/appstore/review-notes-2.1.0.md` (English) with placeholder `[LIMITED-TEST-API-KEY]`; no real key committed.
