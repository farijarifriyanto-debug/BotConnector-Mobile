# iOS/iPadOS BYOK Standalone Client (2.1.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the BotConnector iOS/iPadOS app into a standalone BYOK chat client (Kelivo-style provider flow) with all BotConnector account/billing surface removed, for App Store resubmission as version 2.1.0 build 124.

**Architecture:** Bridge the existing `ByokProviderStore`/`AddProviderSheet` into `ServerStore` (the tested chat path), add a native Anthropic transport, and delete the Cloud account/capability/billing modules and their UI. Chat UI, local models, local pals, and WatermelonDB history are untouched.

**Tech Stack:** React Native 0.82.1, TypeScript, MobX + mobx-persist-store, react-native-keychain, WatermelonDB, jest, GitHub Actions (macos-26).

**Spec:** `docs/superpowers/specs/2026-11-05-ios-byok-2.1.0-design.md`

## Global Constraints

- iOS `MARKETING_VERSION = 2.1.0` and `CURRENT_PROJECT_VERSION = 124` everywhere they appear in `ios/PocketPal.xcodeproj/project.pbxproj`; `scripts/release-preflight.sh` must require exactly `2.1.0`.
- API keys live ONLY in iOS Keychain (services `botconnector.byok.<id>` and `pocketpal-server-<serverId>`); no key in any `console.*` call, analytics, or persisted AsyncStorage/MobX field.
- No new wizard/onboarding gate; send-without-model surfaces a snackbar/prompt to pick a model (existing pattern).
- WatermelonDB schema unchanged — no `src/database/migrations.ts` edit.
- Kelivo core flow parity: preset-or-custom endpoint → API key → fetch model list → pick model → chat.
- Locale files (`src/locales/*.json`): edit per key with the edit tool only; NEVER re-serialize via PowerShell `ConvertTo-Json` (mojibake/`\uXXXX` rule). Run `yarn l10n:validate` after any locale edit.
- Commit messages via `git commit -F <file>` (never inline `-m` with quotes); verify `git branch --show-current` before every commit.
- Tests run with `yarn jest -- <path>`; typecheck `yarn typecheck`; lint `yarn lint`. Baseline must be green before Task 1.
- No BotConnector network call may remain except user-configured BYOK traffic to the preset base URL `https://api.botconnector.id` (and the public marketing site is not called at all).

## Review Focus

1. **Upgrade idempotency:** a user who already saved BYOK providers on the old build must not get duplicate `byok-<id>` servers after update — bridge sync must be idempotent (Task 4 test).
2. **Anthropic non-SSE error body:** a 400/401 from `/messages` arrives as JSON, not an event stream; error mapping must read it without hanging (Task 3 test).
3. **Removing a provider whose model is the active chat model:** the active remote model must be released so chat does not keep calling a deleted endpoint (Task 4 test).
4. **Keychain failure mid-bridge:** `saveProvider` succeeded but the `serverStore.setApiKey` write failed must not leave a server without a key — bridge rolls back (Task 4 test).
5. **Empty model list after a successful fetch:** the picker and Models screen must show the "no models" guidance, not a generic error banner (Tasks 9/10 test).

### Task 3: Anthropic native transport

**Files:**
- Create: `src/api/anthropic.ts`

- Modify: `src/api/openai.ts` (`fetchModels` dispatch point — see Step 3)

**Interfaces:**
- Produces: `export async function streamAnthropicCompletion(params: StreamChatParams, endpoint: RemoteEndpoint, signal?: AbortSignal, onToken?: (data: CompletionStreamData) => void): Promise<CompletionResult>` — same contract as `streamChatCompletion` in `src/api/openai.ts:464`.
- Produces: `export async function fetchAnthropicModels(url: string, apiKey?: string, timeoutMs?: number): Promise<RemoteModelInfo[]>` — native `GET {base}/models?limit=1000`, headers `x-api-key`, `anthropic-version: 2023-06-01`, `Authorization: Bearer`.
- Consumes: `SSEParser` from `src/api/sseParser`, `normalizeUrl`/`resolveTimeout`/`CONNECTION_TIMEOUT_MS`/`IDLE_TIMEOUT_MS` from `src/api/http`, `bodyExtras` from `src/api/servers`, `encodeMessagesForRemote`-equivalent image inlining — export the image-encoding helper from `openai.ts` for reuse (it is currently module-private around lines 290-436).

Behavior (full-featured, per approved spec §4):
- POST `{base}/messages`, headers as above + `Content-Type: application/json`, `Accept: text/event-stream`.
- Request body: `model`, `max_tokens` (Anthropic requires it: from `n_predict` sampler via `bodyExtras`, default `4096` when absent), `system` lifted out of the messages array (concatenate multiple system messages with `\n\n`), `messages` with user/assistant roles only, `stop_sequences` from `params.stop`, `temperature`/`top_p` via `bodyExtras`, `stream: true`.
- Tools: map OpenAI-shaped `tools`/`tool_choice` → Anthropic `tools` (`input_schema`) and `tool_choice` (`{type:'auto'|...}`); assistant `tool_calls` in history → `tool_use` content blocks; role-`tool` messages → user messages with `tool_result` blocks.
- Vision: base64 image attachments become `{type:'image', source:{type:'base64', media_type, data}}` blocks on user messages.
- Thinking: send `thinking` from `bodyExtras`; parse `thinking_delta`/`signature_delta` blocks into `reasoning_content` so the existing reasoning UI renders it.
- SSE parse: `content_block_delta` (text_delta/thinking_delta/input_json_delta), `content_block_start` (tool_use → begin a tool call accumulator), `message_delta` (`stop_reason`, `usage` → timings), `message_stop` → finish. Rebuild streamed `tool_use` partial JSON like the OpenAI tool-call accumulator in `openai.ts:503`.
- Errors (XHR `onload` non-2xx, JSON body `{error:{message}}`): 401/403 → `Unauthorized: Invalid or missing API key`; 429 → rate-limit message; other → `Server error: <status>` with ≤200 chars of detail. Connection/idle timeout + abort semantics identical to the OpenAI path.
